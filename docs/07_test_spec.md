## 1. テスト方針

### 1.1 テスト戦略

本アプリケーションは単一 HTML ファイルで動作するブラウザアプリケーションであり、バックエンドを持たない。テストは以下の 3 層で構成する。

```
テストピラミッド:
        △
       ╱ ╲
      ╱ ST ╲        ← 少数・重要シナリオのみ手動実行
     ╱───────╲
    ╱   IT    ╲     ← 機能間連携の自動テスト（Jest）
   ╱───────────╲
  ╱     UT      ╲   ← 計算ロジックの自動テスト（Jest）
 ╱───────────────╲
```

### 1.2 テストスコープ

| テスト対象 | テスト種別 | 自動化 |
|-----------|----------|-------|
| 収容量計算ロジック | 単体テスト | ○ |
| バリデーションロジック | 単体テスト | ○ |
| 通路検出アルゴリズム | 単体テスト | ○ |
| 自動配置アルゴリズム | 単体テスト | ○ |
| データ保存・読込 | 単体テスト | ○ |
| LocalStorage マイグレーション | 単体テスト | ○ |
| 提案書算出ロジック | 単体テスト | ○ |
| UI 操作・キャンバス描画 | 手動テスト | △ |
| エクスポート出力物 | 手動テスト | △ |
| 複数ブラウザ動作 | 手動テスト | ✕ |

### 1.3 テスト実行タイミング

| タイミング | 実行するテスト |
|-----------|-------------|
| 機能実装後 | 関連する単体テスト |
| フェーズ完了時 | 全単体テスト + 結合テスト + システムテスト |
| リリース前 | 全テスト + クロスブラウザテスト + 回帰テスト |

### 1.4 合格基準

| テスト種別 | 合格基準 |
|-----------|---------|
| 単体テスト | 全ケース PASS（0 FAIL） |
| 結合テスト | 全ケース PASS（0 FAIL） |
| システムテスト | 高優先度テスト 100% PASS、中優先度 95% 以上 PASS |
| 回帰テスト | 前バージョンで動作した機能が 100% 維持 |
| パフォーマンス | ラック 200 個で 60fps 以上 |
